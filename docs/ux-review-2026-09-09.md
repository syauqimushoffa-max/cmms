# UX review — 9 September 2026

## Implemented

- Shared navigation: page titles, plant context, working profile links, actionable notification links, notification retry feedback, keyboard dismissal, skip links, and focus handling in mobile navigation.
- Work-order queue: URL-backed filters retained through browser Back, result counts, reset filters, explicit loading and retry states, visible delete failures, named filter controls, and collapsed advanced filters on phones.
- Work-order creation: local calendar dates, clearer description guidance, locked fields during submission, disabled submission until master data loads, and reuse of the created work-order ID when retrying a failed photo upload.
- Public requests: a failed photo upload no longer presents a successfully created request as a failed submission. Guest tracking explains the partial result. Copy/share failures provide recovery guidance.
- Dashboard, reports, performance, assets, spare parts, and TV board: improved failure feedback. Initial analytics loading is distinguished from zero activity; partially refreshed performance data is identified.
- People and settings: searchable accounts, visible password-length guidance, accurate access labels, and save controls disabled until integration settings load.
- Technician experience: work history available from More, accurate profile roles, real push notification controls, and clearer installation/connection guidance.
- Shared controls: searchable dropdown arrow-key selection and focus management, photo-viewer focus restoration, photo-limit guidance, visible focus indicators, reduced-motion support, and mobile form sizing.
- Recovery: missing-page navigation, an application error boundary, offline guidance, and preservation of existing sessions when account loading fails because of a connection interruption.

Photo-failure recovery was inspected in code; browser checks did not deliberately fail a real upload. Use staging for these integration checks before production rollout.
